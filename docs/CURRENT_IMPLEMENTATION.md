# Roclint — product and implementation overview

Roclint is a resident native prompt-engineering application built with C++20, Qt Quick/QML and SQLite. The supplied Stardust v4.2 product contracts guide the implementation.

The AST correctness baseline is sealed at `deadd39` with workspace/scope epochs,
failed-cache invalidation, meaningful bounded renderer identity and automatic
stale-path recovery. [Baseline verification](audit/ast_baseline_verification_2026-11-05.md)
records the Windows reproductions and gates. The optional development-only
[evaluation runner](audit/phoenix_evaluation_baseline_2026-11-05.md) has a 30-case
AST / six-case native rewrite smoke set and local Phoenix publication/readback.
Semantic rewrite acceptance, held-out datasets and native macOS validation remain
separate gates. Phoenix is not a desktop application dependency.

The [expanded grounded-rewrite evaluation](audit/grounded_evaluation_v2_2026-11-05.md)
freezes 100 AST and 100 rewrite cases. Its original baseline passed AST 100/100
and rewrite grounding/mechanical checks 48/100. The
[AST/rewrite remediation](audit/ast_rewrite_tuning_2026-11-06.md), application
commit `bbc05e5`, passes 100/100 in each suite, including held-out groups, with
zero wrong Verified bindings. It adopts exact qualified-target boundaries,
preserves explicit file/scope constraints and strengthens the rewrite contract's
distinction between AST metadata and user requirements. Agent editorial review
still flags two wording concerns; human fidelity/usefulness adjudication and
native macOS checks remain open. Mechanical success is not release-quality
semantic acceptance. The earlier isolated experiment remains historical evidence.

The original upstream HUD/dashboard design and workspace/scope controls are retained. [Upstream integration](UPSTREAM_INTEGRATION.md) records the subsequent compatibility pass and intentional command/runtime changes. The default shortcut is Ctrl/Cmd+Shift+L; saved user preferences take precedence.

## Normal workflow

1. Focus the prompt field in a supported application and invoke Roclint using the configured global shortcut. Alternatively, open the HUD and type or paste a draft explicitly. Opening Roclint never imports the clipboard automatically.
2. Review or edit the captured draft, optionally clearing the one-shot coarse app-category hint.
3. With the HUD open, pause typing for 800 ms to check the latest draft automatically, or choose **Review prompt** for deeper review, including after a low S1 score. Draft persistence completes before analysis starts. Julia/S1 first classifies the frozen prompt. Automatic checks use its existing threshold/dead band; explicit review can invoke Granite regardless of that score. Results distinguish ready, one useful question, and optional assistance. Original wording remains available. An unavailable scorer cannot establish a clear route.
4. Resolve consequential questions explicitly or keep the original. Creative directions and task decomposition are optional help. The final confirmation can start a Granite rewrite preview; quiet prompts can instead request **Improve wording** without inventing a decision. A remaining decision after the three guided questions stays visible and can be resolved with an explicit manual answer; it is never silently accepted.
5. Inspect the locally computed diff and specific answers, and acknowledge required review items. Technical scores, internal statuses and routine mechanical checks are hidden by default and accessible through Technical details. The original revision remains immutable throughout this review.
6. Approve the exact wording to copy it back. Optional ambient capture can deliver into a supported captured field, with stale checks and clipboard fallback.

The explicit paste/copy workflow works without a workspace selection or accessibility permissions. Closing the widget leaves the tray/menu-bar host resident; Quit exits it.

Automatic checks consume only the latest edited draft after a pause. Hiding/minimizing the HUD, clearing the draft, explicit cancellation, or storage failure cancels a pending check. Failed and cancelled drafts are not automatically retried; a fresh edit or explicit Review prompt is required. No automatic check approves or sends text. After confirmed insertion, the delivery echo is ignored and new typing in the same captured composer can start the next check. HUD-owned edits and an unapproved review remain protected from unrelated source observations.

Enable **Settings → Live prompt capture** to observe the focused editable field in Codex desktop (whose Windows executable is `ChatGPT.exe`), VS Code, Cursor, Windsurf, Antigravity and the listed IDEs. Pause typing to display **Check prompt**, then click it or use the configured global shortcut to review the captured draft. Capture preserves whitespace and includes short prompts. No model runs on every keystroke. A visible HUD does not suspend macOS capture while the source editor owns foreground focus. Before review, live capture follows the focused supported draft; during review, a real text change in the same captured field invalidates old decisions/proposals and starts the debounced check. Mere focus return or an unrelated field does not replace the review. Actual HUD-authored edits and history restores stay authoritative until the user explicitly adopts an editor draft again.

An empty editable composer is also a valid destination: invoke Roclint from that field, author a draft in the HUD, and approve insertion into the captured empty field. Invocation gives Chromium a bounded opportunity to expose its editor before the HUD takes focus. Optional `ROCLINT_CAPTURE_DIAGNOSTICS` logs provider role, target token, character count and failure flags; it never logs prompt content or selections.

Insertion restores and verifies the exact field focus and confirms the replacement by reading it back. The HUD preserves its chosen presentation after insertion. On failure it shows the reason and offers the approved text through the clipboard; an explicitly hidden HUD is not reopened by the callback. Roclint never presses Send/Enter in the target editor. Unsupported fields require Copy and manual paste; application identity alone does not guarantee that its editor exposes a usable accessibility provider.

Generated alternatives are checked against a deliberately narrow, deterministic color-bound rule. An unquoted explicit English requirement such as “will be black” or “cannot be blue”, grounded by the alternative's source spans, can block a generated reversal or a narrowed prohibition. Blocked alternatives remain in the saved model artifact but are disabled with a reason in the HUD, rejected by controller commands, and rechecked before rewriting restored intent. Quoted data and compound terms such as black-box are excluded. This is not a complete natural-language constraint validator; scope changes can be supplied explicitly through a manual answer and all rewrites still require review.

## AST grounding reliability — November 5, 2026

The code index now uses schema v5 with per-file `snapshot_generation`/`dirty` membership plus separate `last_refresh_complete` and `coverage_complete` flags. A full refresh advances the workspace generation; `refreshPaths` carries forward only previous-generation eligible files, records and dirties unprocessed paths, and revalidates the requested saved paths, so unrelated unchanged files remain grounded. Missing, unreadable and oversized files are invalidated rather than retained as current evidence. Queries require current snapshot membership and cannot surface older cached rows; `SymbolQueryResult.complete` propagates coverage independently of truncation.

A bounded recursive `CodebaseWatcher` observes the consented workspace, debounces file/directory events and schedules validation. Notifications are hints only: selected source hashes are rechecked before evidence is promoted, and hash-detected stale paths initiate bounded, coalesced reindexing (at most three attempts per path, reset by validated grounding). A healthy watcher also uses the existing five-minute fallback for missed creation/deletion events. Atomic saves, renames, deletions, bursts and directory changes fall back to safe refresh behavior. A running partial watcher is retained through overflow/failure with its fallback cadence; a stopped watcher gets at most three backoff attempts before stable degraded mode, and explicit refresh/workspace reselection is the deliberate recovery path. Indexing, parsing, hash validation and grounding run off the UI thread; superseded workspace callbacks are rejected. Incomplete full scans and paths passes retry boundedly, then withhold until a later successful pass.

The symbol model records syntactic roles, declaration/definition sites, parameter order and declared type syntax, const/reference/static/inline/constexpr/variadic/template flags, qualifiers and body-free `signatureKey` values. Extraction covers globals, multiple declarators, anonymous namespaces, out-of-class methods, constructors/destructors/operators, representative templates and function pointers, while omitting unsupported macro-generated and ambiguous forms. No implementation bodies are stored or injected.

Exact grounding accepts qualified names, explicit `in <scope>` and `file <relative-path>` constraints, parameter name/`#position`, and supported syntactic overload signatures. Explicit constraints outrank focus; truncated, dirty or incomplete candidate sets cannot prove uniqueness or absence and remain `Ambiguous` with `complete=false`. Grounded prompt XML is capped at 350 bytes, a valid worst-case 350-token bound for the pinned byte-level BPE; signatures retain a separate 300-byte sub-limit. A Verified record is emitted only with a non-blank target, either complete or explicitly marker-truncated; records that cannot carry identity are omitted from the rendered subset, hash and HUD. The renderer returns the exact rendered subset, and only that evidence enters the proposal-v2 hash/display. Workspace and active-file scope changes carry an epoch; they immediately invalidate old proposals/approvals and make old discovery/rewrite/grounding tickets stale. Refresh completion re-resolves a pending proposal and clears it on new ambiguity/removal, failed/unavailable validation, or a superseded workspace epoch while preserving equivalent unrelated changes. Proposal-v1 compatibility is unchanged.

Fresh verification on Windows: Release build passed; `50/50` CTests passed in `210.07 s`; Python `49` tests passed with one platform skip; structure `94/94` with `0` errors; the verification probe passed `9/9`; the 13-case grounding corpus resolved `13/13` with coverage `1.0`, `0` wrong `Verified` results and `0` status mismatches; all previous review reproductions and the four second-review boundary findings were corrected. ## Implementation

- `app/host`: host/controller, shortcut registration, passive host context, screen placement, native Granite/Julia supervisors, explicit model installer, development Ollama client, optional accessibility bridges and terminal draft extraction.
- `app/runtime`: pinned native llama.cpp helper/engine, Julia worker, model/configuration manifests and benchmark fixtures.
- `app/qml/shell`: compact prompt/review widget, settings/history and optional ambient badge.
- `include/roclint` and `src`: core revisions, normalized analysis, materiality, intent, rewrite/approval validation and SQLite storage.
- `tests`: core/storage/bridge/host suites and a QML keyboard workflow test.

Native Granite uses a pinned local Granite 4.2 3B GGUF and llama.cpp helper with asynchronous startup, strict request binding, cancellation and resource tiers. Both Q4_K_M and Q5_K_M remain benchmark candidates; no evaluation configuration is frozen. Explicit Ollama development mode remains available. Julia uses a separate resident local Python/PyTorch worker with pinned weights, actual inference and snapshot-bound score validation. Julia is the default scorer per the user's explicit request, overriding the original Jev-only restriction. Production Jev remains an unconfigured optional selection. See [native runtime status](NATIVE_GRANITE.md) and [Julia setup and limitations](JULIA_LOCAL_SCORER.md).

The [final scored analysis artifact](FINAL_ANALYSIS_SNAPSHOT.md) persists validated scoring/degradation and presentation order, binds intent/rewrite/approval to its exact hash, and restores that saved evidence without model execution. Schema v5 retains previous pre-score history and requires fresh Analyze/review for it.

No claim of complete offline operation, measured latency, release readiness or macOS validation follows from compiling the Windows development build.

A Granite rewrite created in manual mode has no insertion field, so **Approve & Copy** is an explicit clipboard action. The review now provides **Connect editor…** (or **Change editor…** when already connected): Roclint temporarily hides the HUD, asks the user to focus a destination and invoke the configured shortcut, then attaches that fresh field to the existing review. It preserves the frozen prompt, analysis, confirmed answers, rewrite hash and pending review acknowledgments; it does not call models, approve wording or change the clipboard during connection. The primary footer action offers this connection step when live capture is enabled but no field is bound. After connection, **Approve & Insert** delivers the approved Granite output through the same guarded native path used by as-is insertion. Copy remains available separately. History restores saved sessions directly into review so an ordinary capture invocation cannot accidentally replace the saved rewrite while opening it.

This rewrite-destination build passed 38/38 suites in 85.03 seconds (`build/rewrite-review-complete-tests.log`). The controller regression preserves revision, intent and proposal bindings while selecting a different destination. The actual QML regression creates a manual rewrite with a required semantic review item, connects an editor through the keyboard controls, checks that the item remains unacknowledged, then explicitly reviews and approves it; the resulting injection contains the rewritten text and the destination's exact expected prior text. It also restores the saved review without another model request.
