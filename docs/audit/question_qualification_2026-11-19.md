# Does faster question screening improve Roclint?

## Experiment

Replayed all eight question candidates available in the earlier 17-prompt pilot. Four questions resolve explicit contradictions. Four ask for information already supplied, require the developer to perform the requested classification or code inspection, or ask about scope after the user specified all invoice reads. The latter is a poor question even though the underlying security-sensitive request merits review. Screening a question and resolving a security concern are separate decisions.

Each call supplied the complete original draft and the candidate question inside the rendered instructions. An identical constrained schema returned ask, skip, or uncertain. The primary test was whether the gate directly retained useful questions and suppressed unnecessary ones. An uncertain result would need an explicit fallback in production. No repository contents were supplied to the gate.

Local Q8_0 Granite 4.2 3B, Metal, pinned runtime settings. Three fresh worker sessions, one per mode. All used the same executable linked from the current build with a benchmark-only switch forwarding the GGUF template's low_effort parameter. Thinking-off used the existing request flag. The ordinary analysis profile caps reasoning at 384 tokens. Each mode used the same eight inputs in the same order, one observation per cell. Timings exclude loading and include native request/response. Mode order was fixed. This is a short semantic screening call, distinct from the earlier two-quote conflict verifier. Four useful questions came from the verifier and four unnecessary questions came from discovery, so wording and source are confounded with the correct disposition. There was no independent human rating, editor replay, new held-out sample or execute-and-compare step.

## Question outcomes

| Mode | Median seconds | Useful questions accepted | Unnecessary questions suppressed | Uncertain |
| --- | ---: | ---: | ---: | ---: |
| off | 0.64 | 2/4 | 3/4 | 2/8 |
| low | 9.92 | 2/4 | 2/4 | 1/8 |
| bounded | 10.22 | 2/4 | 2/4 | 2/8 |

Thinking-off suppressed the already-supplied feedback and CRC questions, but it also suppressed the valid postal-code include/omit question. Low effort suppressed the valid parser question. An uncertain-to-review fallback preserves uncertain cases while still missing definitive wrong skips. These results favor testing qualification inside discovery and collecting independent held-out questions before automatic suppression.

## Julia scope and security

Six paired CPU probes preserved the original text and inserted manual role annotations. For the genuine XML/JSON conflict, the direct conflict score moved from .462 to .990. For the genuine parser contradiction it moved from .043 to .688. But the compatible parser demonstration also moved from .401 to .999. Both known sentiment false positives remained above .60. This measures manually supplied role hints, not an automatic scope extractor. Compare clause-pair extraction on unseen prompts with examples that carry binding requirements as well as incidental demonstrations.

The security head scored the two positive cases .068 and .196 and the quoted prohibition .999. On these fixed inputs any threshold catching both positives also flags at least 10 of the other 15. Positive temperature scaling within one binary head preserves rank. A larger labeled dataset is needed to fit probabilities and compare the current head with scope-aware deterministic signals and a purpose-built model. Measure genuine requests, quotations, prohibitions and remediation language separately, and preserve uncertain cases. IBM publishes Guardian 2B with custom risk definitions. Its usefulness on this particular decision requires a local evaluation. [IBM Guardian model card](https://huggingface.co/ibm-granite/granite-guardian-3.0-2b)
